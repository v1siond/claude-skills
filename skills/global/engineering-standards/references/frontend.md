# Frontend code rules

The rules for writing frontend code in any of his repos, read by the frontend player while it builds and by
the architect when it draws the component tree. How the screen is designed: skill ui. A project's own
frontend facts: its project skill (SKILLS.md).

## Components render, modules decide

- A business rule lives in the backend and is tested there (skill testing-standard,
  `references/test-modes.md`).
- A plain frontend module (TypeScript or JS) holds UI logic only: a display calculation, a transform for the
  screen. It is tested only in `add browser tests`, when he names a plain-function test for the batch; `default` writes 0 frontend tests.
- A component only reads state, renders and wires events.
- A component that grows a rule moves the rule out first, as its own change, behaviour unchanged.

## Served data

- A value the backend owns (a limit, a label, a setting, a catalog) is read from the backend, never typed in
  the frontend. A `const` in the frontend has no control he can edit.
- One loader per resource. Every screen that needs the resource reads it through that loader.
- Read served values inside a function at render time, never at module scope: a module level read freezes
  the empty catalog that existed before the fetch.
- No fallbacks that invent a value when the served one is missing; show the missing state.
- Parse the served object whole; a hand-listed field list drops whatever is served next.

## State

- Each piece of state has one owner (component, hook or store). Others read it from there or get it passed
  down; nobody keeps a copy.
- Derived values are computed, never stored next to their source.
- A heavy view (a map, a canvas, a large list) sits in its own component tree, apart from the editor UI around
  it, so a change in UI state does not re-render it.

## Markup and styles

- Controls come from the repo's kit (skill ui). A new control is added to the kit first, then used.
- Tailwind first, ITCSS for the rest, no inline styles (law 10); a `style` that only sets a CSS variable for a
  dynamic value is the one exception.
- Class names are literals in the source. A class assembled at runtime is never generated by Tailwind; when
  a dependency supplies them, add it to the content globs, or `safelist` a class with no literal anywhere.

## Gates

- Typecheck and lint exit 0 (`references/stacks.md`). `default` writes 0 frontend tests of any kind; component
  tests never; browser tests only in the `add browser tests` mode (skill testing-standard).
